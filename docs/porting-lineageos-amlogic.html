00

Kelayakan device

Tujuan: membuktikan STB mau menjalankan image yang bukan dari operator.

Ini fase paling penting dan paling sering dilewati orang. Kalau bootloader unit kamu terkunci rapat, semua kerja device tree jadi sia-sia. Selesaikan ini sebelum menyentuh apa pun.

Baca identitas board

adb
adb shell getprop | grep -E "ro.board.platform|ro.product.device|ro.build.version|ro.treble.enabled"
adb shell ls -l /dev/block/by-name/     # layout partisi: ada 'super'?
adb shell cat /proc/meminfo | head -1
adb shell cat /proc/cpuinfo | tail -20

ro.board.platform harus g12a (B860H V5) atau gxl (HG680P). Kalau bukan, seluruh dokumen ini tidak berlaku untuk unit kamu.

Uji burn mode

Sambungkan STB ke PC dengan kabel USB A-to-A male lewat port USB yang dekat catu daya, lalu masuk burn mode: tekan tombol reset di lubang AV/pinhole pakai tusuk gigi sambil menyalakan daya. Di Windows, USB Burning Tool harus mendeteksi "Connect success". Kalau tidak terdeteksi sama sekali di semua port, unit kamu belum siap.

Uji boot dari luar eMMC

Cara termurah membuktikan u-boot mau menjalankan image asing: tulis Armbian ke microSD atau flashdisk dan coba boot. Kalau Armbian jalan, artinya aml_autoscript dieksekusi dan u-boot tidak memaksa signature — itu lampu hijau untuk LineageOS.

Secure boot

Sebagian unit STB operator di-fuse dengan kunci vendor, sehingga u-boot dan boot image tanpa tanda tangan langsung ditolak. Gejalanya: burn mode terdeteksi tapi flash selalu gagal di tahap bootloader, dan tidak ada image SD apa pun yang mau boot. Kalau ini kasusnya, hentikan proyek di unit tersebut dan cari unit dengan revisi board atau versi OTA lain.

Checkpoint

Burn mode terdeteksi, Armbian dari SD/USB berhasil boot, dan kamu sudah mencatat ro.board.platform serta daftar partisi by-name.

01

Backup & jaring pengaman

Tujuan: apa pun yang rusak nanti, bisa dikembalikan ke kondisi pabrik.

Jangan dilewati

Tanpa dump eMMC, satu kesalahan flash bootloader mengubah STB jadi barang mati permanen. Dengan dump, hampir semua kesalahan bisa dibalik. Ini satu-satunya asuransi yang benar-benar bekerja — bukan SD boot, bukan "hati-hati".

Dump eMMC penuh

Cara paling praktis: boot Armbian dari SD (sudah kamu buktikan di Fase 00), lalu salin seluruh eMMC ke flashdisk.

armbian · shell
lsblk                                  # cari device eMMC, biasanya mmcblk0 / mmcblk1
dd if=/dev/mmcblk1 of=/mnt/usb/stock-emmc-full.img bs=8M status=progress
sha256sum /mnt/usb/stock-emmc-full.img > /mnt/usb/stock-emmc-full.sha256

# simpan juga per-partisi penting untuk referensi cepat
dd if=/dev/mmcblk1boot0 of=/mnt/usb/bootloader-boot0.img
cat /proc/partitions > /mnt/usb/partitions.txt

Simpan artefak stock

  • DTB stock — jadi bahan baku Fase 05.
  • Firmware pabrik dalam bentuk aml_upgrade_package.img kalau tersedia di komunitas untuk versi OTA unitmu.
  • Foto PCB dua sisi resolusi tinggi — untuk mencari pad UART, test point eMMC, dan menentukan revisi board.
  • Catatan chip WiFi — baca tulisan di modul kaleng WiFi, ini menentukan Fase 06.

Siapkan jalur unbrick sebelum dibutuhkan

  • Kabel USB A-to-A male, tusuk gigi, dan pinset untuk short pad eMMC.
  • USB Burning Tool terpasang di Windows dengan driver WorldCup device sudah dikenali.
  • Adaptor USB-TTL 3.3V (CH340/CP2102) untuk serial console — akan sangat menentukan di Fase 10.
Checkpoint

Dump eMMC penuh tersimpan di dua lokasi berbeda dengan checksum tercatat, dan kamu sudah pernah sekali berhasil me-restore-nya lewat USB Burning Tool.

05

DTS kernel

Tujuan: satu file DTS yang menggambarkan board kamu, bukan board referensi Amlogic.

Ini bagian yang paling menentukan apakah device boot atau layar tetap gelap. Kabar baiknya, kamu tidak mulai dari nol — kernel LineageOS sudah membawa DTS board referensi yang menjadi basis kedua STB ini.

Ambil DTB stock

bash
adb shell su -c 'dd if=/dev/block/dtb of=/sdcard/dtb.img'
adb pull /sdcard/dtb.img

# partisi dtb Amlogic biasanya container multi-DTB (magic 'AML_DT'),
# berisi beberapa DTB untuk varian RAM berbeda — pisahkan dulu,
# lalu decompile yang sesuai kapasitas RAM unitmu
dtc -I dtb -O dts -o stock.dts single.dtb

Pilih DTS basis dan diff

DeviceDTS basis di kernel LineageOS
B860H V5arch/arm64/boot/dts/amlogic/g12a_s905x2_u212.dts
HG680Parch/arm64/boot/dts/amlogic/gxl_p212_2g.dts

Yang hampir selalu berbeda antara board referensi dan STB produksi, urut dari yang paling sering bikin gagal boot:

  1. Tabel partisi — node partitions menentukan seluruh by-name yang dilihat Android.
  2. Timing dan kapasitas DDR — salah di sini berarti kernel panic sangat awal, atau layar mati total.
  3. PHY ethernet — alamat MDIO dan reset GPIO berbeda antar vendor.
  4. Node SDIO WiFi — sd_emmc_a di GXL (sdio@d0070000), lengkap dengan GPIO power enable.
  5. IR receiver, LED indikator, tombol reset — nomor GPIO khas tiap board.

Simpan hasilnya sebagai file DTS baru di direktori yang sama, daftarkan di Makefile kernel, lalu tulis namanya (tanpa .dts) ke TARGET_DTB_NAME.

Alamat controller berbeda per keluarga

Nilai androidboot.boot_devices tidak sama antar SoC. GXL: d0074000.emmc untuk eMMC dan d0072000.sd untuk kartu SD. G12A: ffe07000.emmc dan ffe05000.sd2. Salah nilai berarti Android tidak menemukan satu partisi pun.

Checkpoint

DTS baru terkompilasi bersih saat build kernel, dan daftar partisi di dalamnya cocok persis dengan by-name yang kamu catat di Fase 00.

06

WiFi & Bluetooth

Tujuan: wlan0 muncul dan bisa scan.

Upstream LineageOS hanya menyediakan modul kernel Amlogic untuk rtl8822bs, rtl8822cs, Broadcom dhd-driver, dan rtk_btusb. Di luar itu, kamu yang menyediakan.

B860H V5 — sudah tersedia

Kalau modul WiFi unitmu memang RTL8822CS, cukup daftarkan modul yang sudah ada dan tarik hardware/realtek. Tidak ada pekerjaan driver sama sekali.

BoardConfig.mk
TARGET_KERNEL_EXT_MODULES := \
    rtl8822cs/rtl88x2CS:kbuild

Buka casing dan baca tulisan di modul WiFi sebelum mengasumsikan ini — revisi board V5 tidak seragam.

HG680P — harus ditambahkan

Dua varian, dan chip-nya berbeda:

  • Casing hitam — RTL8189FS, antarmuka SDIO
  • Casing putih — RTL8188FU, antarmuka USB

Ambil driver out-of-tree Realtek yang sesuai, port ke kernel 4.9, taruh di kernel/amlogic/kernel-modules/<nama>/ dengan kbuild sendiri, lalu daftarkan di TARGET_KERNEL_EXT_MODULES.

Sisi HAL

  • BOARD_WLAN_DEVICE, BOARD_WPA_SUPPLICANT_PRIVATE_LIB, dan BOARD_HOSTAPD_PRIVATE_LIB harus cocok dengan vendor chip.
  • Firmware dan konfigurasi diletakkan sesuai init.amlogic.wifi.rc milik common tree.
  • Bluetooth Realtek lewat rtk_btusb; kalau unitmu tidak punya BT, set BOARD_HAVE_BLUETOOTH := false supaya manifest BT tidak ikut dibangun.
Strategi build pertama

Jangan tunggu WiFi beres. Build pertama sebaiknya tanpa WiFi sama sekali dan mengandalkan ethernet. Boot dulu sampai UI muncul, baru kembali ke fase ini. Debugging WiFi di atas sistem yang belum pernah boot itu menebak dua variabel sekaligus.

Checkpoint

Modul .ko terbentuk di vendor_dlkm atau vendor/lib/modules, dan lsmod di device menampilkannya setelah boot.

09

Instalasi

Tujuan: image berjalan di device, dengan risiko yang kamu pilih sendiri.

Tiga jalur, urut dari yang paling aman. Untuk build pertama, pakai Jalur A.

Jalur A — Boot dari SD atau USB (non-destruktif)

Ini jalur bring-up yang benar: eMMC stock tetap utuh, dan setiap percobaan gagal cukup dibalas cabut kartu. Upstream g12-common sudah menyediakannya lengkap dengan varian tanpa AVB.

BoardConfig.mk
TARGET_BOOTDEVICE := sdcard      # atau: usb

Efeknya: cmdline berubah ke androidboot.boot_devices=ffe05000.sd2, dan fstab beralih ke fstab.sdcard.amlogic yang memetakan /data ke mmcblk1p5 serta /metadata ke mmcblk1p2. Varian fstab_no_avb.sdcard.amlogic mematikan verifikasi — pakai itu selama pengembangan.

Untuk mengarahkan u-boot ke kartu tanpa menulis eMMC, taruh aml_autoscript di partisi FAT kartu — mekanisme yang sama persis dipakai multiboot Armbian.

Perlu diverifikasi sendiri

Di mode sdcard, entri /boot, /dtbo, /misc, dan /recovery masih memakai node by-name Amlogic. Cek ke mana node itu benar-benar resolve di unitmu sebelum menyimpulkan eMMC tidak tersentuh sama sekali.

Untuk HG680P, blok TARGET_BOOTDEVICE dan fstab.sdcard.amlogic belum ada di gx-common — salin polanya dari g12-common dan ganti alamat controller ke d0072000.sd.

Jalur B — USB Burning Tool (permanen)

Jalur untuk pemakaian sehari-hari. Perlu aml_upgrade_package.img yang berisi bootloader, DTB, dan seluruh image.

  1. Ambil paket firmware stock sebagai kerangka, bongkar dengan imagepacker di hardware/amlogic/tools/imagepacker.
  2. Ganti isinya dengan hasil build: boot.img, recovery.img, super.img atau trio system/vendor/odm, dan DTB baru.
  3. Repack, lalu flash lewat USB Burning Tool dengan opsi Erase flash aktif supaya tabel partisi ikut diganti.

Cek sintaks imagepacker langsung dari source-nya — parameternya berbeda antar versi tool.

Jalur C — Recovery sideload (update berikutnya)

bash
adb reboot recovery
adb sideload out/target/product/b860hv5/lineage-*.zip

Baru bisa dipakai setelah LineageOS Recovery terpasang lewat Jalur B. Ini jalur normal untuk semua pembaruan setelah instalasi pertama.

Checkpoint

Device menyala, logo Amlogic lewat, dan minimal ada output di serial console — meski UI belum muncul.

10

Bring-up & debugging

Tujuan: dari layar gelap ke launcher Android TV.

Serial console dulu

Sebelum menebak apa pun, sambungkan UART. Cari tiga atau empat pad bertanda RX / TX / GND di PCB, pakai adaptor USB-TTL 3.3V, dan buka pada 115200 8N1. Tanpa serial kamu buta terhadap semua kegagalan sebelum adbd hidup — dan justru di situlah sebagian besar masalah bring-up terjadi.

BoardConfig.mk · aktifkan console kernel
WITH_CONSOLE := true
# menambahkan: console=ttyS0,115200 no_console_suspend ignore_loglevel

11

Finishing & rilis

Tujuan: layak dipakai orang lain, bukan cuma booting.

Remote control

Remote IR bawaan operator memakai kode NEC yang tidak dikenal Android. Buat file keylayout — dopinder memakai pola nama keylayout/Vendor_0001_Product_0001.kl. Petakan minimal: arah, OK, Back, Home, Menu, dan volume.

Tampilan

  • Overlay resolusi default, DPI, dan kompensasi overscan lewat rro_overlays/.
  • Set mode HDMI default yang aman (1080p60) supaya tidak ada unit yang boot ke layar kosong.

Signing & OTA

bash
# generate kunci rilis sendiri — jangan pakai test-keys untuk build publik
./development/tools/make_key ~/.android-certs/releasekey  '/CN=Lineage/'
# lalu build ulang dengan kunci tersebut

Hal yang perlu dijelaskan ke pemakai

  • Widevine turun ke L3. Kunci HDCP pabrik tidak ikut, jadi Netflix dan Disney+ hanya SD. Ini permanen, bukan bug.
  • GApps Android TV opsional dan menambah beban di RAM 2 GB. Sediakan varian tanpa GApps.
  • Sertifikasi hilang — device tidak lagi Google-certified, sebagian aplikasi TV akan menolak jalan.
Checkpoint

Semua tombol remote berfungsi, resolusi benar sejak boot pertama, build ditandatangani kunci sendiri, dan ada dokumentasi flash untuk orang lain.
